# Plan: v0.6 Release — Polish + Refactor

## Goal
Ship v0.6 with two changes: (1) remove dead code/UI, (2) split the 2201-line `window.py` monolith into focused modules. No new features.

---

## Part 1: Polish

### 1A. Remove dead checksum checkbox
- **File**: `src/launcher/gui_qt/window.py` (Settings dialog, ~line 1740)
- Remove the "Verify file integrity" checkbox from `_show_settings`
- Remove `check_integrity` from `Config.load_settings` / `save_settings` in `config.py`
- **Why**: Checkbox exists in UI but the feature was never implemented. Dead UI confuses users.

### 1B. Remove legacy DPG GUI
- **Delete**: `src/launcher/gui_dpg/` directory (window.py, theme.py, __init__.py)

- **Why**: DPG GUI is incomplete, discontinued, and adds dead weight. PySide6 is the only GUI now.

## Part 2: Refactor window.py (2201 lines → 8 modules)

### Architecture
`LauncherApp` becomes the **application controller** — owns managers, wiring, lifecycle. Pages are QWidget subclasses that receive managers via constructor. Shared helpers (worker, signaler) become standalone modules.

### Module Split

| # | New File | Source Lines | What It Contains |
|---|----------|-------------|------------------|
| 1 | `gui_qt/worker.py` | 30-32, 165-177 | `_UISignaler`, `Worker` — threading primitives |
| 2 | `gui_qt/widgets.py` | 52-54, 76, 82-159 | `HeroBanner`, resource path constants, `SIDEBAR_W` |
| 3 | `gui_qt/game_page.py` | 413-516, 917-956, 967-1010 | `GamePage(QWidget)` — game management page + status/progress helpers |
| 4 | `gui_qt/tools_page.py` | 518-676, 1012-1142 | `ToolsPage(QWidget)` — region editor + zip extractor |
| 5 | `gui_qt/mods_page.py` | 678-834, 1144-1439 | `ModsPage(QWidget)` — BepInEx, profiles, mod list |
| 6 | `gui_qt/profile_page.py` | 836-885, 1943-2144 | `ProfilePage(QWidget)` — itch.io auth, profile display |
| 7 | `gui_qt/dialogs.py` | 1685-1882 | `SettingsDialog`, `AboutDialog` — extracted inline dialogs |
| 8 | `gui_qt/window.py` | Remaining ~800 lines | `LauncherApp` — orchestrator: init, tray, sidebar, game actions, update checker, lifecycle |

### Shared State Solution
- **Managers** (`config`, `network`, `discord`, `game`, `region_mgr`, `profile_mgr`): Stay on `LauncherApp`, passed to pages via constructor
- **Threading** (`_run`, `_invoke_main`): Stay on `LauncherApp`, passed to pages as callbacks
- **Status updates** (`_set_status`, `_busy_on`/`_busy_off`): Stay on `LauncherApp`, passed as callbacks
- **Cross-page updates** (`_update_profile_ui` writes to both game page + profile page): `ProfilePage` emits a `profileUpdated` signal; `LauncherApp` connects it to update game page labels
- **`self.window`**: Passed as parent to pages for dialog parenting

### Implementation Order
1. Create `worker.py` and `widgets.py` (zero coupling, safe to extract first)
2. Create `dialogs.py` (Settings + About, simple extraction)
3. Create `game_page.py` (most-used page, moderate coupling)
4. Create `tools_page.py` (region + zip, self-contained)
5. Create `mods_page.py` (BepInEx + profiles + mods, most complex)
6. Create `profile_page.py` (itch.io, cross-page signal needed)
7. Slim down `window.py` to orchestrator
8. Test all pages still work

### Safety Rules
- **One commit per module extraction** — easy to revert if something breaks
- **No behavior changes** — pure refactor, same UI, same features
- **Keep all imports working** — no `__init__.py` changes needed, modules are imported directly
- **Preserve existing code style** — no comments, no docstrings, match existing patterns
